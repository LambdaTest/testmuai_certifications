Adding a form in JavaScript instead would mean cloning markup and incrementing TOTAL_FORMS by hand, and a management form that disagrees with the posted data raises rather than validates. Empty slots cost nothing — AnswerOptionForm.has_changed() reports an untouched slot as unchanged, so Django skips it rather than saving a blank row. The correct-answer control is a button, not a radio. Django names each option's is_correct separately (answers-0-is_correct), so they cannot form a native radio group; the hidden input beside each button carries the real value, and "on" / "" is exactly what CheckboxInput reads back as True / False. With JavaScript off nothing is marked, and the formset's clean() says so plainly rather than saving a question with no correct answer. Marks

{% comment %} One input, not two. It is hidden for an objective question rather than replaced by a hidden field, because two inputs sharing the name `marks` would both post and the form would read whichever came last. Hidden or not it still posts, and QuestionForm.clean() overwrites it with Exam.MARKS_PER_QUESTION for objective questions — Exam.total_marks_for() multiplies count by that constant rather than summing real questions, so one question worth 7 makes every randomised paper's maximum marks wrong. {% endcomment %}

{% comment %} Uploads, not dropdowns. associated_image / _audio / _video are ForeignKeys, so a plain ModelForm would render three pickers of existing rows — and those models carry no caption, so every entry would read "Image object (3)". QuestionForm declares three FileFields under separate names instead, and creates the row on save. The bylines print the limits from forms.py rather than stating a number here, so the promise and the check cannot drift apart. They are still only bylines: `accept` filters the file picker and nothing more, and Django applies no upload ceiling of its own. The enforcement is the max_size validator on each field. SVG is deliberately absent from the image list: it is XML, it can carry an inline script element, and MEDIA_URL is same-origin. MP4 and WebM only for video — MOV, AVI and MKV upload fine and then fail silently in the video player, which a candidate would discover mid-exam. (Written without angle brackets on purpose. Django strips this block at render, but an editor's HTML parser does not know that: a literal script tag here puts it into raw-text mode and every line after it is reported as broken.) {% endcomment %}
