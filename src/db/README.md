# src/db — schema and migrations

Drizzle schema, migrations, and the database client. Nothing else. No business logic — that lives
in `src/core`, which calls into here.

```
schema/       Table definitions, one file per domain area, re-exported from index.ts
migrations/   Generated by drizzle-kit. Forward-only. Never edit an applied migration.
```

## Connections

- The app uses the **pooled** connection string (`DATABASE_URL`). Serverless functions open many
  short-lived connections; the unpooled string will exhaust Postgres.
- Migrations use the **direct** string (`DATABASE_URL_UNPOOLED`) — PgBouncer in transaction mode
  cannot handle DDL reliably. Already wired in `drizzle.config.ts`.

## Rules

- **Constraints belong here, not in application code.** `UNIQUE`, `CHECK`, foreign keys. They
  catch what code review misses, and this product cannot tolerate impossible states — a response
  without a question, a score above the maximum, two bookings for one seat.
- **All timestamps are `timestamptz`, stored UTC.** Display conversion happens at the edge. Exam
  slots and timers are the whole product; a timezone bug means someone misses their exam.
- Public identifiers — credential IDs above all — must be **unguessable**. Never sequential.
- Soft-delete anything referenced by historical attempts. Questions and exam versions must remain
  readable forever.

## Expected tables

Not yet specified in detail — `docs/data-model.md` is pending the code-execution decision. The
shape is roughly:

```
users                external_id (opaque, unique), email, name, role
certifications       name, slug, level, description, icon, external_ref (nullable)
exam_versions        certification_id, status, duration_minutes, pass_mark, published_at
sections             exam_version_id, title, weight, position
questions            type, stem, payload (jsonb), answer_key (jsonb), tags, status
exam_version_questions  join: version, question, section, position, weight
exam_slots           exam_version_id, starts_at, ends_at, timezone, capacity, registration_closes_at
bookings             slot_id, candidate_id, status          UNIQUE(slot_id, candidate_id)
attempts             booking_id, exam_version_id, started_at, expires_at,
                     submitted_at, graded_at, result_released_at
attempt_questions    frozen served set + order, per attempt
attempt_responses    attempt_id, question_id, response (jsonb), score
                                                       UNIQUE(attempt_id, question_id)
credentials          attempt_id, public_id (unguessable), issued_at, expires_at, revoked_at
attempt_events       append-only audit log
```

`answer_key` lives on `questions` and must never be selected in a candidate-facing query. See
[`docs/conventions.md`](../../docs/conventions.md#answer-key-safety).
